# Alexa RTSP Bridge Pro — first-time installation

**Preview v0.4.0b1.** This guide assumes you have **never created an Alexa Smart Home skill, AWS Lambda function or Cloudflare Tunnel**. The guided setup in the dashboard offers 11 steps, with links and copyable values. It doesn't ask for your AWS credentials, Amazon password or Cloudflare token.

The local RTSP/HLS gateway has been exercised with eight real NVR channels on a previous build. The **new wizard and Alexa integration require real end-to-end acceptance testing**; don't call an installation validated based on a snapshot alone.

1. **Prepare Home Assistant.** Install it from [official instructions](https://www.home-assistant.io/installation/), create a camera entity and enable `alexa: smart_home:` with an explicit include filter. Your HA login must work via public HTTPS.
2. **Install the gateway.** On Ubuntu/Docker, clone `https://github.com/RenanEspinar/Alexa-RTSP-Bridge`, copy `.env.pro.example` to `.env.pro`, and start `docker compose --env-file .env.pro -f compose.pro.yml up --build -d`. The local dashboard is bound to `127.0.0.1:18099` and signed HLS to `127.0.0.1:18090` by default. Do **not** publish the unauthenticated dashboard directly.
3. **Add a camera.** In the wizard use a private RTSP URL, Auto mode, then run Codec, JPEG and HLS checks. A successful segment check is not Alexa playback proof.
4. **Create HTTPS access.** Set up a [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/get-started/). Protect the separate admin hostname with [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/). Publish the HLS media port under a different HTTPS hostname **without interactive Access login**, since Alexa fetchers cannot perform it. Unauthenticated, unsigned media requests should return HTTP 403.
5. **Create an Alexa Skill.** In [Amazon Developer Console](https://developer.amazon.com/alexa/console/ask), with the Amazon account you use on your devices, create a **Smart Home** Skill with **Provision your own**, payload v3. Copy the Skill ID.
6. **Create Lambda.** In [AWS IAM](https://console.aws.amazon.com/iam/), create a role for Lambda with `AWSLambdaBasicExecutionRole`. In [AWS Lambda](https://console.aws.amazon.com/lambda/), choose a region compatible with your Alexa locale, Python 3.13 or another supported Python version, and handler `lambda_function.lambda_handler`. Paste [this project’s Lambda code](https://github.com/RenanEspinar/Alexa-RTSP-Bridge/blob/main/aws/lambda_function.py), Deploy, add an Alexa Smart Home trigger restricted to your Skill ID and copy the function ARN. In the Skill's Smart Home service endpoint, paste the ARN.
7. **Configure Lambda.** Add `HOME_ASSISTANT_URL`, `ALEXA_HLS_BASE`, `HLS_SIGNING_KEY`, `CAMERA_ENDPOINT_MAP_JSON` to Environment variables. The wizard copies the map and secret into the clipboard. Check real Alexa endpoint IDs — do not guess IDs from HA entity names. An empty `{}` mapping allows discovery before you know the endpoint IDs.
8. **Enable OAuth account linking.** Authorization Code Grant, credentials in request body; `https://HA_HOST/auth/authorize`, `https://HA_HOST/auth/token`, scope `smart_home`; select the geographic Client ID using [Home Assistant’s authoritative guide](https://www.home-assistant.io/integrations/alexa.smart_home/) and set Client Secret there. Do not confuse it with the HLS signing key.
9. **Test on the Alexa app/device.** Alexa app → Skills & Games → Your Skills → Dev → enable the Skill and log into HA. Discover devices. Ask Fire TV/Echo Show to display one camera and confirm live, moving video. Review Lambda logs if discovery works but video doesn't.

For screenshots, exact field values, error cases, region-specific Client IDs, security rules and troubleshooting, see the [detailed Spanish beginner manual](WIZARD_DESDE_CERO_ES.md) and [Home Assistant’s official Alexa instructions](https://www.home-assistant.io/integrations/alexa.smart_home/).
